# CI/CD

> PR을 올린 순간부터 `main`에 들어가 배포될 때까지, **사람이 확인하지 않아도 자동으로 걸러지는 것**을 정리한다.
> 무엇을 지켜야 하는가는 [`CONTRIBUTING.md`](../CONTRIBUTING.md)에 있고, 이 문서는 **그중 무엇이 기계로 강제되는가**를 다룬다.

---

## 1. CI/CD가 무엇인가

**CI (Continuous Integration, 지속적 통합)** — 각자 작업한 코드를 자주 공용 브랜치에 합치고,
합칠 때마다 자동 검사를 돌린다. 목적은 검사 자체가 아니라 **통합 비용을 뒤로 미루지 않는 것**이다.
3주치를 한 번에 합치면 무엇이 깨뜨렸는지 사람이 찾아야 하지만, 하루치씩 합치면 범위가 커밋 하나로 좁혀진다.

**CD**는 두 가지 뜻으로 쓴다.

| 용어 | 뜻 | 사람이 개입하는 지점 |
|---|---|---|
| Continuous Delivery (지속적 제공) | 언제든 배포 가능한 산출물까지 자동으로 만들어 둔다 | 배포 실행 |
| Continuous Deployment (지속적 배포) | 검사를 통과하면 운영까지 자동으로 나간다 | 없다 |

이 저장소의 `site/`는 **Continuous Deployment**다. `main`에 들어가면 사람 손 없이 배포된다.

### 게이트가 핵심이다

검사를 돌리는 것과 **검사를 통과해야 머지되는 것**은 다르다.
GitHub 브랜치 보호에 등록한 검사만 머지 버튼을 잠근다. 등록하지 않은 검사는 빨간불이어도 그냥 들어간다.
그래서 CI 문서에서 실제로 중요한 표는 4절이다.

---

## 2. 지금의 파이프라인

```
작업 브랜치 push
      │
      ▼
   PR 생성 ──┬─ PR 규약 · convention   제목 형식 / 이슈 연결 / 변경 규모
             ├─ 문서 · links           마크다운 상대 링크  (.md 변경 시에만)
             └─ Vercel Preview         PR별 미리보기 URL
      │
      │  필수 검사 통과 + 승인 1명 + 열린 리뷰 스레드 없음
      ▼
 Squash merge ──▶ main ──▶ Vercel 배포 (site/)
```

아직 `backend/`·`frontend/` 코드가 없어서 **빌드·테스트 단계가 없다.**
현재 CI가 지키는 것은 코드 품질이 아니라 **히스토리와 문서의 일관성**이다.

## 3. 워크플로

### 3.1 PR 규약 — [`.github/workflows/pr-convention.yml`](../.github/workflows/pr-convention.yml)

PR이 열리거나, 제목·본문이 수정되거나, 새 커밋이 push될 때 실행된다.

| 검사 | 기준 | 결과 |
|---|---|:---:|
| 제목 형식 | `<타입>(<스코프>): <내용>` — 타입 7종, 스코프 `be`·`fe` | **실패** |
| 제목 길이 | 72자 초과 | **실패** |
| 제목 길이 | 50자 초과 | 경고 |
| 이슈 연결 | 본문에 `Closes #N` (`Fixes`·`Resolves`도 인정) | 경고 |
| 변경 규모 | 500줄 초과 | 경고 |
| 변경 규모 | 300줄 초과 | 안내 |

**제목만 실패로 둔다.** Squash merge에서 PR 제목이 그대로 `main`의 커밋 메시지가 되기 때문이다.
머지되고 나면 고치려면 히스토리를 다시 써야 하고, 그건 되돌릴 수 없는 종류의 실수다.

**이슈 연결은 경고다.** 규약(CONTRIBUTING 3절)이 이슈를 **원칙으로 두되 강제하지 않기** 때문이다.
오타 하나 고치는 PR까지 이슈를 요구하면 이슈가 사후 정당화용으로 찍히고, 그 순간 이슈는
"하려는 일"이 아니라 형식이 된다. 이슈가 필요한 변경인지는 리뷰어가 판단한다.

경고를 남기는 이유는 따로 있다. **이슈를 만들어놓고 연결만 빠뜨린 경우**가 실제로 잦고,
그러면 머지돼도 이슈가 닫히지 않아 남은 일 목록이 틀어진다. 이 경고는 그걸 잡으라고 있는 것이지
이슈를 만들라고 있는 것이 아니다.

**변경 규모는 경고다.** 정적 자산이나 생성 파일처럼 쪼개도 리뷰 단위가 나뉘지 않는 경우가 있고,
그때는 PR 본문에 사유를 적는 것으로 갈음한다.

### 3.2 문서 — [`.github/workflows/docs.yml`](../.github/workflows/docs.yml)

모든 PR과 `main` push에서 [`check-md-links.py`](../.github/scripts/check-md-links.py)를 돌린다.
**마크다운의 상대 링크가 실제 파일을 가리키는지** 검사한다.

문서끼리 서로를 참조하고 README가 이들을 가리키는 구조라, 파일명이 바뀌면 링크가 조용히 깨진다.
아무도 클릭해보기 전까지는 모른다.

외부 URL(`http`·`https`·`mailto`)은 **일부러 검사하지 않는다.** 네트워크에 의존하면
남의 서버가 잠깐 죽었다는 이유로 우리 CI가 빨간불이 된다.

### 3.3 Vercel 배포 — [`vercel.json`](../vercel.json)

| 항목 | 값 |
|---|---|
| 배포 대상 | `site/` (`outputDirectory`) |
| 빌드 | 없다. 정적 HTML을 그대로 올린다 |
| 프로덕션 배포 | `main` push |
| 프리뷰 배포 | PR마다 별도 URL |
| URL 규칙 | `cleanUrls` — `.html` 확장자 없이 접근 |

GitHub Actions가 아니라 Vercel의 GitHub 연동이 직접 감지해서 돈다. 저장소에 워크플로 파일이 없는 이유다.

## 4. 무엇이 머지를 막는가

`main` 브랜치 보호에 **필수 상태 검사로 등록된 것만** 머지 버튼을 잠근다.

| 검사 | 실행되는가 | 머지를 막는가 |
|---|:---:|:---:|
| `convention` (PR 규약) | 항상 | **예** |
| `links` (문서) | 항상 | **예** |
| Vercel Preview | 항상 | 아니오 |

### paths 필터와 필수 검사는 같이 못 쓴다

`links`는 원래 `paths: '**.md'` 필터가 걸려 있어 `.md` 변경이 없는 PR에서는 실행되지 않았다.
GitHub의 필수 상태 검사는 **"성공"을 기다리지 "실행되지 않음"을 통과로 치지 않는다.**
그 상태로 등록하면 코드만 바꾼 PR이 영원히 대기 중으로 잠긴다. 그래서 필터를 걷어내고 등록했다.

**앞으로 추가할 잡도 같은 제약을 받는다.** 모노레포에서 BE/FE 잡을 경로로 가르는 것은 맞지만,
필수로 올릴 잡은 해당 경로 변경이 없을 때 **빠르게 성공으로 끝나야** 한다. 실행 자체를 건너뛰면 안 된다.

### 검사 외의 잠금

| 설정 | 값 |
|---|---|
| 직접 push | 금지 |
| 승인 필요 수 | 1 (부재 시 예외 절차는 CONTRIBUTING 9절) |
| 새 커밋 시 승인 무효화 | 예 |
| 리뷰 대화 해소 필수 | 예 |
| 선형 히스토리 | 강제 |
| force push · 브랜치 삭제 | 금지 |
| 관리자에게도 적용 | 예 |

---

## 5. 검사가 실패했을 때

**제목 형식 실패** — PR 제목을 고치면 워크플로가 다시 돈다. 브랜치에 커밋을 새로 올릴 필요가 없다.

**링크 검사 실패** — 로컬에서 그대로 재현된다. CI와 같은 스크립트다.

```bash
python3 .github/scripts/check-md-links.py
```

깨진 링크가 파일명과 줄 번호로 나온다. 앵커(`#섹션`)는 검사하지 않고 파일 경로만 본다.

**Vercel 프리뷰가 안 뜰 때** — 배포 로그는 PR에 붙는 Vercel 코멘트에서 본다.
`site/` 밖의 변경은 배포 결과에 영향을 주지 않는다.

---

## 6. 앞으로 추가할 것

코드가 들어오는 시점에 맞춰 넣는다. 지금 미리 만들어두면 돌릴 대상이 없어 그냥 빈 잡이 된다.

| 시점 | 추가할 검사 | 필수 등록 |
|---|---|:---:|
| `backend/` 첫 커밋 | 컴파일 · 단위 테스트 | 예 |
| `frontend/` 첫 커밋 | 타입 검사 · 빌드 | 예 |
| 1단계(정원 초과 재현) 이후 | 불변식 검출기 — 위반 0건 확인 | 예 |
| 통합 테스트 도입 시 | Testcontainers 기반 PostgreSQL · Redis | 예 |

**path 필터를 쓸 거면 필수 등록과 같이 설계한다.** 4절에서 `links`가 걸렸던 함정이 그대로 반복된다.
