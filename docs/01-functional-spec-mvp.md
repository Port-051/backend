# 게임 파티 자동 매칭 서비스 기능 명세서 — MVP

## 문서 범위

- 이 문서는 최초 구현 단계에서 만들 기능만 정의한다.
- 대상 게임은 **리그 오브 레전드 하나**이며 한국 서버를 기준으로 한다.
- 서비스 대상은 국내 이용자이며 모든 일정은 한국 표준시를 기준으로 한다.
- 신원은 **Discord 계정**으로 확인한다. 서비스 자체 회원가입과 비밀번호 로그인은 제공하지 않는다.
- 알림은 **Discord 다이렉트 메시지**로 보낸다. Web Push는 사용하지 않는다.
- 일치도 점수, 조건 자동 완화, 반복 예약, 평가·차단·신고, 과거 이용 내역과 운영자 화면은 포함하지 않는다.
- 이 문서가 정의하지 않는 분산 전제·불변식·측정 기준은 `02-technical-spec-supplement.md`에 있다.

## 1. 신원과 기본 정보

### 1.1 Discord 로그인

- 서비스 이용은 Discord OAuth2 로그인으로 시작한다.
- 최초 로그인 시 Discord 계정 식별자를 서비스 계정에 연결한다.
- 요청·제안·확정 파티 상태는 계정에 귀속한다.
- 기기나 브라우저를 바꿔도 같은 Discord 계정으로 로그인하면 상태가 이어진다.

### 1.2 다이렉트 메시지 수신 설정

- Discord는 서버를 공유하지 않는 상대의 다이렉트 메시지를 기본으로 차단할 수 있다.
- 로그인 직후 Bot이 시험 메시지를 보내 수신 가능 여부를 확인한다.
- 수신할 수 없는 상태이면 해결 방법을 안내한다.
  - 서비스 Discord 서버에 참여하는 방법
  - 개인정보 설정에서 서버 멤버의 다이렉트 메시지를 허용하는 방법
- 수신 불가 상태에서는 매칭 신청을 할 수 없다.
- 사용자가 설정을 바꾼 뒤 다시 확인할 수 있게 한다.

### 1.3 국내 서비스 고정

- 국가·지역 선택 기능을 제공하지 않는다.
- 언어 설정과 언어 기반 매칭을 제공하지 않는다.
- 롤은 한국 서버를 기준으로 한다.
- 예약 시간은 모두 한국 표준시로 표시한다.

### 1.4 기본 프로필

- 서비스에서 사용할 닉네임을 설정한다.
- 초기값은 Discord 표시 이름을 사용하며 사용자가 변경할 수 있다.
- 음성채팅 조건을 `필수`, `가능`, `사용하지 않음` 중에서 선택한다.
- 플레이 목적을 선택한다.
  - 가볍게 즐기기
  - 승리·랭크 상승
  - 초보자 학습
  - 숙련자 중심 플레이
- 플레이 분위기를 `편안함`, `적당한 집중`, `높은 집중도` 중에서 선택한다.
- **플레이 분위기는 매칭 조건으로 사용하지 않는다.** 확정 파티 상세에만 표시한다.

> 플레이 분위기를 조건으로 쓰지 않는 이유는 플레이 목적과 의미가 겹치기 때문이다.
> 조건 축이 늘어날수록 후보가 갈려 매칭 성립률이 떨어진다.

## 2. 롤 계정 연동

### 2.1 Riot ID 등록

- `게임 이름#태그` 형식의 Riot ID를 한 번 등록한다.
- 한국 서버의 계정을 조회한다.
- 등록한 Riot ID가 본인 계정인지는 검증하지 못한다는 점을 화면에 표시한다.
- 서비스가 Riot 계정 비밀번호를 직접 입력받지 않는다.

### 2.2 조회 정보

- Riot 공식 API를 통해 다음 정보를 자동으로 가져온다.
  - 솔로·듀오 랭크 티어·단계·LP
  - 자유 랭크 티어·단계·LP
  - 승·패
  - 배치 진행 또는 언랭크 여부
- 솔로·듀오 랭크와 자유 랭크를 구분해 표시한다.
- 매칭에 필요한 요약 정보만 다른 참가자에게 공개한다.
- Riot ID 전체는 파티 확정 이후에만 공개한다.

### 2.3 연결 상태와 갱신

- 연결 상태를 `정상`, `확인 필요`, `조회 실패`로 표시한다.
- 마지막 정보 갱신 시각을 표시한다.
- 저장된 정보가 신선도 기준을 넘기면 자동으로 다시 조회한다.
- 사용자가 직접 `새로고침`을 눌러 갱신할 수 있다.
- 신선도 기준과 호출 정책은 `02-technical-spec-supplement.md` 5장에서 정의한다.

### 2.4 기본 포지션

- 프로필에 주 포지션과 부 포지션의 기본값을 설정한다.
  - 탑 / 정글 / 미드 / 바텀 / 서포터
- 주 포지션은 하나만 선택한다.
- 부 포지션은 선택하지 않거나 하나 이상 선택할 수 있다.
- `상관없음`을 선택하면 다섯 포지션 전부를 부 포지션으로 취급한다.
- 이 값은 매칭 요청 생성 시 초기값으로 채워지며, 요청마다 다르게 바꿀 수 있다.
- 매칭에 사용하는 것은 **요청에 담긴 값**이며 프로필 값이 아니다.

## 3. 매칭 요청 생성

### 3.1 즉시 매칭

- `지금 바로 플레이`를 선택한다.
- 최대 대기시간을 선택한다.
- **예상 플레이시간을 선택한다.**
- 파티가 확정되면 시작 시각은 확정 시각으로, 종료 예정 시각은 확정 시각에 예상 플레이시간을 더한 값으로 정한다.
- 대기 시작 후 현재 상태와 경과 시간을 보여준다.

> 예상 플레이시간은 화면 표시용이 아니다. 이 값이 없으면 파티에 종료 시각이 없어
> 시간이 겹치는 중복 배정(불변식 INV-2)을 판정할 수 없다.

### 3.2 일회성 예약 매칭

- 원하는 날짜와 시작 시각을 선택한다.
- 오늘 날짜의 예약은 신청할 수 없으며 다음 날 이후만 선택한다.
- 예상 플레이시간을 설정한다.
- 시작 가능 범위를 선택한다.
  - 정확한 시각
  - 앞뒤 30분 가능
  - 앞뒤 1시간 가능
- 예약 매칭은 플레이 당일 00시에 실행되며 성립한 파티는 별도의 수락 없이 자동 확정된다는 점을 신청 전에 안내한다.

### 3.3 예약 마감 경계

- 화면에 표시하는 신청·수정 마감은 **플레이 전날 23시 50분**이다.
- 실제 처리 경계는 배치 실행 시작 시각 `T`이며, `T` 이전에 생성되고 상태가 `예약됨`인 요청만 그날 배치의 대상이 된다.
- `T` 이후 도착한 신청과 수정은 해당 배치에 포함하지 않는다.
- 표시 마감과 실제 경계 사이의 10분은 안전 여유이며, 이 구간에 들어온 요청은 처리하되 보장하지 않는다.

> 표시 마감과 처리 경계를 분리하는 이유는, 마감 시각과 배치 시각이 같으면
> 경계에 걸친 요청의 처리 여부가 정의되지 않아 멱등성(불변식 INV-3)을 검증할 수 없기 때문이다.

### 3.4 큐와 인원

- 한 요청에는 큐 하나만 선택한다.
  - 솔로·듀오 랭크
  - 자유 랭크
  - 일반
- 큐별로 선택할 수 있는 목표 파티 인원이 다르다.

| 큐 | 선택 가능한 목표 인원 |
|---|---|
| 솔로·듀오 랭크 | 2 |
| 자유 랭크 | 2, 3, 5 |
| 일반 | 2, 3, 4, 5 |

- 자유 랭크는 게임 규칙상 4인 파티를 만들 수 없다.
- 혼자 신청하는 방식만 지원한다.
- 친구와 함께 신청하는 기존 파티 기능은 제공하지 않는다.

### 3.5 티어 제약

- 솔로·듀오 랭크는 게임 규칙상 함께 플레이할 수 있는 티어 범위가 제한된다.
- 제약의 형태는 티어 구간에 따라 다르다.
  - 낮은 티어 구간은 티어 단위로 여러 단계까지 허용한다.
  - 중간 티어 구간은 한 티어 위아래만 허용한다.
  - 상위 티어 구간은 티어가 아니라 **단계(디비전) 단위**로 제한한다.
- 구체적인 허용 범위는 **설정 데이터로 관리하며 코드에 고정하지 않는다.**
- 사용자는 본인 티어 기준으로 게임 규칙상 가능한 범위 안에서만 허용 티어 범위를 선택한다.
- 매칭 시 양쪽의 선택 범위를 서로 만족해야 한다.
- 자유 랭크와 일반은 이 제약을 적용하지 않는다.

> 허용 범위를 설정으로 빼는 이유는 라이엇이 시즌마다 이 규칙을 조정하기 때문이다.
> 코드에 고정하면 규칙이 바뀔 때마다 배포해야 한다.

### 3.6 지원하지 않는 티어

- 한국 서버는 마스터 티어 이상 플레이어와 함께 플레이할 수 없다.
- 솔로·듀오 랭크 티어가 **마스터·그랜드마스터·챌린저**인 사용자는 솔로·듀오 랭크 요청을 만들 수 없다.
- 해당 사용자에게 사유를 표시하고 자유 랭크와 일반 큐를 안내한다.
- 자유 랭크와 일반 큐는 티어와 무관하게 이용할 수 있다.

### 3.7 언랭크와 배치 진행

- 솔로·듀오 랭크 티어가 없는 사용자(언랭크 또는 배치 진행 중)는 솔로·듀오 랭크 요청을 만들 수 없다.
- 티어를 확정하면 이용할 수 있음을 안내한다.
- 자유 랭크와 일반 큐는 티어 없이도 이용할 수 있다.
- 티어가 없는 사용자의 티어 표시는 `언랭크` 또는 `배치 중`으로 한다.

> 티어가 없으면 3.5의 허용 범위를 계산할 기준이 없다.
> 임의의 값으로 대체하면 게임에서 큐를 잡지 못하는 파티가 만들어진다.

### 3.8 매칭 조건

- 사용자가 선택한 조건은 모두 반드시 맞아야 하는 조건으로 처리한다.
- `필수 조건`과 `선호 조건`을 구분하지 않는다.
- 조건 항목은 다음과 같다.
  - 큐
  - 목표 파티 인원
  - 허용 티어 범위
  - 주·부 포지션
  - 음성채팅 여부
  - 플레이 목적
- 플레이 분위기는 조건에 포함하지 않는다.

### 3.9 신청 확인과 수정

- 신청 전 큐, 일정, 인원과 모든 조건을 한 화면에 요약한다.
- Discord 다이렉트 메시지 수신 가능 여부를 확인한다.
- 즉시 매칭 요청은 `대기 중` 상태에서만 수정하거나 취소할 수 있다.
- 일회성 예약 요청은 3.3의 마감 규칙에 따른다.
- 취소·수정 요청과 매칭 제안 생성이 동시에 일어나면 **요청 상태 전이에 먼저 성공한 쪽이 이긴다.**
  - 제안 생성이 이겼으면 취소는 실패하고, 사용자에게 제안이 도착했음을 알린 뒤 거절 경로를 제시한다.
  - 취소가 이겼으면 해당 요청은 후보에서 빠지며, 남은 인원으로 정원을 채우지 못한 제안은 생성되지 않는다.

## 4. 자동 매칭

### 4.1 후보 제외

다음 중 하나라도 해당하면 후보에서 제외한다.

- 큐가 다르다.
- 목표 파티 인원이 다르다.
- 플레이 가능한 시간이 겹치지 않는다.
- 서로의 허용 티어 범위를 양쪽 모두 만족하지 않는다.
- 게임 규칙상 함께 플레이할 수 없는 티어다(3.5).
- 음성채팅 조건이 호환되지 않는다(4.2).
- 플레이 목적이 다르다.
- 포지션을 겹치지 않게 배정할 수 없다(4.4).
- 이미 시간이 겹치는 확정 파티에 속해 있다.

### 4.2 음성채팅 호환

- 음성채팅 조건은 `필수`, `가능`, `사용하지 않음` 세 값이며, 값이 다르다고 곧바로 제외하지 않는다.
- 두 사람 사이의 호환 여부는 다음과 같다.

| | 필수 | 가능 | 사용하지 않음 |
|---|:---:|:---:|:---:|
| **필수** | O | O | X |
| **가능** | O | O | O |
| **사용하지 않음** | X | O | O |

- 파티 전체 규칙은 다음과 같다.
  - 참가자 중 한 명이라도 `필수`이면 그 파티는 음성 파티가 되며 `사용하지 않음`인 사람을 넣지 않는다.
  - 참가자가 전부 `가능` 또는 `사용하지 않음`이면 그 파티는 비음성 파티가 된다.
- 확정된 파티의 음성 사용 여부를 파티 상세에 표시한다.

### 4.3 후보 처리 순서

- 모든 조건을 통과한 사람만 후보가 된다.
- 별도의 유사도·신뢰도 점수를 계산하지 않는다.
- 대기시간에 따라 조건을 자동으로 완화하지 않는다.
- 조건이 너무 좁으면 사용자가 요청을 직접 수정해야 한다.
- 후보 처리는 **결정적**이어야 한다. 같은 요청 집합을 입력하면 항상 같은 파티 구성이 나와야 한다.
- 처리 절차는 다음과 같다.
  1. 모든 대기 요청에 `(신청 시각, 요청 ID)` 오름차순으로 전순서를 부여한다.
  2. 아직 배정되지 않은 요청 중 순서가 가장 앞선 것을 기준 요청으로 잡는다.
  3. 기준 요청과 조건이 맞는 후보를 같은 순서로 훑으며, 포지션 배정이 가능한 후보만 차례로 채택한다.
  4. 목표 인원을 채우면 파티를 성립시키고, 채우지 못하면 기준 요청을 그대로 둔 채 다음 요청으로 넘어간다.
  5. 더 이상 성립하는 파티가 없으면 종료한다.

> 순서를 `(신청 시각, 요청 ID)`로 정하는 이유는 신청 시각이 같을 때 순서가 흔들리면
> 배치 재실행 시 결과가 달라져 멱등성(불변식 INV-3)을 검증할 수 없기 때문이다.

### 4.4 포지션 배정

- 한 파티 안에서 두 사람이 같은 포지션을 맡지 않는다.
- 각 참가자는 주 포지션 또는 부 포지션 중 하나를 배정받는다.
- 주 포지션을 배정받은 사람이 많을수록 좋은 배정으로 보되, 배정 가능 여부 자체는 통과·탈락 기준이다.
- 5인 파티는 탑·정글·미드·바텀·서포터를 각각 한 명씩 채운다.
- 2~4인 파티는 포지션이 서로 겹치지 않기만 하면 된다.
- 배정이 불가능한 후보 조합은 파티를 성립시키지 않는다.
- 확정된 파티의 참가자별 배정 포지션을 파티 상세에 표시한다.

### 4.5 매칭 실패 사유 안내

- 최대 대기시간이 지나 매칭에 실패하면 사유를 함께 보여준다.
- 조건을 하나씩 빼가며 각 조건이 후보를 얼마나 줄였는지 계산해 표시한다.
- 가장 많이 줄인 조건을 먼저 보여주고 수정 경로를 제시한다.
- 이 계산은 화면 표시용이며 매칭 결과에 영향을 주지 않는다.

> 조건을 자동으로 완화하지 않는 설계이므로, 왜 실패했는지 알려주지 않으면
> 사용자는 같은 조건으로 무한히 재시도하게 된다.

### 4.6 파티 구성 불변식

- 동시에 여러 매칭이 실행돼도 한 사람이 두 파티에 들어가지 않게 한다.
- 하나의 요청은 동시에 하나의 파티 구성에만 포함한다.
- 확정된 파티의 인원은 목표 인원을 넘지 않는다.
- 위 항목의 형식 정의와 검출 방법은 `02-technical-spec-supplement.md` 2장에 있다.

## 5. 즉시 매칭 제안과 수락

### 5.1 제안 도착

- 즉시 매칭에서 후보 파티가 만들어지면 참가자 전원에게 동시에 제안을 보낸다.
- 큐, 시작 시각, 인원, 배정 포지션과 일치한 조건을 보여준다.
- 상대방의 Riot ID와 Discord 계정은 확정 전까지 공개하지 않는다.
- 남은 수락 시간을 실시간으로 표시한다.

### 5.2 수락·거절

- 사용자는 제안을 수락하거나 거절한다.
- 수락 후 다른 참가자의 응답 현황을 익명으로 보여준다.
- 제한시간까지 응답하지 않으면 자동 거절로 처리한다.
- 중복 클릭이나 네트워크 재전송에도 같은 요청을 한 번만 처리한다.
- 거절한 사람이 누구인지는 다른 참가자에게 공개하지 않는다.

### 5.3 확정과 재매칭

- 즉시 매칭은 필요한 인원이 전부 수락했을 때만 파티를 확정한다.
- 한 명이라도 거절하거나 시간초과되면 해당 제안을 종료한다.
- 이미 수락했던 정상 이용자는 기존 대기 순서를 유지한 채 다시 대기한다.
- 사용자는 `계속 찾기` 또는 `매칭 종료`를 선택한다.

### 5.4 실패 조합 재제안 억제

- 조합은 참가 요청 식별자의 집합으로 정의한다.
- 실패한 조합은 실패 시각으로부터 **10분간** 다시 제안하지 않는다.
- 구성원이 한 명이라도 다르면 다른 조합으로 취급하며 억제 대상이 아니다.
- 억제 기록은 10분이 지나면 자동으로 사라지며 영구 보관하지 않는다.
- 억제 기록은 인스턴스가 여러 대여도 공유되어야 한다.

## 6. 진행 중 요청과 예약 관리

### 6.1 현재 요청 확인

- 로그인한 계정의 진행 중인 요청을 보여준다.
- 다음 상태를 표시한다.
  - 예약됨
  - 매칭 대기 중
  - 수락 대기 중
  - 매칭 확정
  - 재매칭 중
  - 취소됨
  - 매칭 실패
  - 이탈함
  - 완료됨
- 서버 내부 처리 단계는 사용자에게 노출하지 않는다.
- 과거에 완료된 파티 목록은 제공하지 않는다.

### 6.2 이탈 후 처리

- 확정 파티에서 스스로 나간 요청은 `이탈함` 상태로 종료한다.
- 이탈한 요청은 자동으로 다시 대기하지 않는다. 새 요청을 만들어야 한다.
- 파티가 취소되어 참가자 전원이 빠지는 경우는 `취소됨`으로 처리한다.

## 7. 확정 파티 관리

### 7.1 파티 상세

- 큐, 시작·종료 예정 시각, 참가 인원과 합의된 조건을 표시한다.
- 참가자의 서비스 닉네임, 티어 요약, 배정 포지션, 플레이 분위기를 보여준다.
- 확정 이후에만 Riot ID와 Discord 사용자명을 공개한다.
- 파티가 음성 파티인지 여부를 표시한다.
- 합류는 게임 클라이언트에서 직접 한다. 서비스는 Discord 전용방을 만들지 않는다.

### 7.2 준비 확인

- 시작 전에 `참여 가능`, `늦을 예정`, `참여 불가` 중 하나를 선택한다.
- 아직 응답하지 않은 인원 수를 보여준다.

### 7.3 확정 후 이탈

- 확정된 파티에서 나갈 수 있다.
- 이탈 사유와 시각을 기록한다.
- 시작 직전 이탈에는 경고를 보여준다.
- 이탈을 처리한 직후 남은 인원을 판정한다.
  - 남은 인원이 **2명 미만**이면 파티 전체를 취소하고 참가자에게 알린다.
  - 남은 인원이 2명 이상이면 파티를 유지하고 빈자리를 공개 모집으로 전환한다(7.4).
- 여러 명이 동시에 이탈해도 각 이탈 처리마다 순차적으로 판정한다.

### 7.4 빈자리 공개 모집

- 이탈로 생긴 빈자리는 **비어 있는 포지션 단위의 좌석**으로 공개한다.
- 조건이 맞는 대기 중인 사용자에게 모집 중인 좌석 목록을 보여준다.
- 지원 자격은 **지원자와 기존 참가자 전원** 사이에서 판정하며, 기준은 다음과 같다.
  - 큐와 목표 인원이 파티와 같다.
  - 지원자가 그 좌석의 포지션을 주 또는 부 포지션으로 맡을 수 있다.
  - 기존 참가자 전원과 티어 조건을 서로 만족한다.
  - 파티가 음성 파티이면 지원자의 음성채팅 조건이 `사용하지 않음`이 아니다.
  - 플레이 목적이 파티의 합의된 목적과 같다.
  - 시간이 겹치는 확정 파티에 속해 있지 않다.
- 지원은 **선착순으로 즉시 확정**하며 기존 참가자의 수락 절차를 거치지 않는다.
- 좌석이 채워지면 즉시 마감하고, 이후 도착한 지원은 실패로 응답한다.
- **여러 명이 같은 좌석에 동시에 지원해도 정원을 넘겨 확정하지 않는다.**
- 좌석이 채워지면 기존 참가자에게 새 참가자를 알린다.

> 이 절이 정원 초과(불변식 INV-1)를 만드는 유일한 경로다.
> 전원 수락으로만 확정하는 5장 경로에서는 좌석을 놓고 경쟁하는 사람이 없어 경합이 발생하지 않는다.

### 7.5 모집 마감과 인원 확정

- 모집은 파티 시작 예정 시각 **10분 전**에 마감한다.
- 마감 시점의 인원으로 파티를 확정하되, 다음 경우에는 파티를 취소한다.
  - 인원이 2명 미만이다.
  - 인원이 해당 큐에서 허용되지 않는 수다.
- 자유 랭크는 4인 파티를 만들 수 없으므로, 5인 자유 랭크 파티가 4인으로 마감되면 취소한다.
- 목표 인원에 못 미치지만 큐 규칙상 허용되는 인원이면 그대로 진행하고, 줄어든 인원과 빈 포지션을 참가자에게 알린다.

### 7.6 완료 처리

- 종료 예정 시각이 지나면 파티를 완료 상태로 전환한다.
- 파티원 평가나 신고를 요청하지 않는다.

## 8. 알림

### 8.1 인앱 실시간 상태

- 새로고침 없이 대기·제안·수락·확정 상태를 갱신한다.
- 연결이 끊기면 자동 재연결한다.
- 재연결 후 현재 상태를 다시 불러온다.
- 참가자가 서로 다른 애플리케이션 인스턴스에 붙어 있어도 같은 시점에 전달한다.

### 8.2 Discord 다이렉트 메시지

- 다음 내용을 Discord 다이렉트 메시지로 알린다.
  - 즉시 매칭 제안 도착
  - 수락 제한시간 임박
  - 매칭 확정
  - 빈자리 충원 완료
  - 인원 감소로 인한 변경
  - 파티 취소
  - 시작 전 준비 확인
- 다이렉트 메시지 전송에 실패하면 인앱 상태로만 안내하고 실패를 기록한다.
- 같은 알림을 두 번 보내지 않는다.

### 8.3 예약 리마인더

- 파티 시작 24시간 전, 1시간 전, 10분 전에 알린다.
- 이미 취소된 파티에는 알림을 보내지 않는다.
- 파티가 취소되면 아직 발송되지 않은 알림을 회수한다.

## 9. 예외 처리

### 9.1 외부 정보 오류

- Riot ID 형식 오류, 존재하지 않는 계정, 언랭크와 API 장애를 구분한다.
- Discord 권한 거절, 다이렉트 메시지 차단과 Bot 장애를 구분한다.
- 기존 조회 정보가 있으면 마지막 갱신 시각을 함께 표시한다.
- Riot API 장애 중에는 저장된 정보로 매칭을 계속하되 갱신 실패를 표시한다.

### 9.2 매칭 오류

- 시간이 겹치는 요청을 중복 생성하지 못하게 한다.
- 여러 사용자가 동시에 응답하거나 지원해도 파티 정원을 초과하지 않게 한다.
- 만료된 제안에 응답하면 최신 상태를 다시 보여준다.
- 이미 마감된 좌석에 지원하면 마감 사실을 알리고 목록을 갱신한다.
- 다시 접속하면 현재 진행 상태를 복구한다.

### 9.3 시간 오류

- 이미 지난 시각으로 예약하지 못하게 한다.
- 오늘 날짜의 일회성 예약은 신청하지 못하게 한다.
- 3.3의 마감을 지난 예약은 새로 만들거나 수정하지 못하게 한다.

## 10. 자동 처리

### 10.1 일회성 예약 매칭 배치

- 매일 00시 한국 표준시를 기준으로 당일 일회성 예약 매칭을 한 번 실행한다.
- 3.3의 경계 규칙에 따라 대상 요청을 결정한다.
- 4.3의 결정적 절차로 파티를 구성한다.
- 매칭된 파티는 별도의 수락 절차 없이 자동 확정한다.
- 파티를 구성하지 못한 예약은 매칭 실패로 종료한다.
- 미래 날짜의 예약은 해당 플레이 날짜 00시가 될 때까지 처리하지 않는다.
- 작업 장애로 배치가 재실행되거나 두 인스턴스에서 동시에 실행되더라도 사용자가 여러 파티에 중복 배정되지 않게 한다.

### 10.2 즉시 매칭 만료

- 최대 대기시간이 지나면 즉시 매칭 요청을 자동 종료한다.
- 종료 시 4.5의 실패 사유를 함께 제공한다.
- 수락 제한시간이 지나면 해당 즉시 매칭 제안을 자동 거절 처리한다.

### 10.3 외부 정보 동기화

- Riot 정보의 갱신 주기를 관리한다.
- 신선도 기준 안의 정보는 다시 호출하지 않고 저장된 값을 사용한다.
- 동일 계정에 대한 동시 조회를 하나로 합친다.
- 외부 API 호출 제한과 일시 장애에 대응한다.

### 10.4 알림 작업

- 파티 확정 시 예약 리마인더 작업을 생성한다.
- 파티 취소 시 남은 알림 작업을 회수한다.
- 동일한 알림을 중복 발송하지 않는다.

## 11. MVP 완료 기준

- [ ] Discord 계정으로 로그인하고 기기를 바꿔도 상태가 이어진다.
- [ ] 다이렉트 메시지 수신 가능 여부를 확인하고 해결 방법을 안내할 수 있다.
- [ ] Riot ID를 등록하고 티어 정보를 자동으로 가져올 수 있다.
- [ ] 티어에 따라 선택 가능한 큐와 허용 티어 범위를 제한할 수 있다.
- [ ] 즉시 매칭과 일회성 예약을 만들 수 있다.
- [ ] 매일 00시에 당일 일회성 예약을 매칭하고 성립한 파티를 자동 확정할 수 있다.
- [ ] 조건이 일치하는 사람을 결정적 순서로 구성할 수 있다.
- [ ] 5인 파티를 포지션이 겹치지 않게 배정할 수 있다.
- [ ] 매칭 실패 시 어느 조건이 후보를 가장 많이 줄였는지 보여줄 수 있다.
- [ ] 동시에 매칭해도 사용자가 중복 배정되지 않는다.
- [ ] 즉시 매칭 제안과 전원 수락을 처리할 수 있다.
- [ ] 실패한 즉시 매칭 제안의 정상 이용자를 재대기시킬 수 있다.
- [ ] 확정 파티의 준비 확인과 이탈을 관리할 수 있다.
- [ ] 이탈로 생긴 빈자리를 공개 모집하고, 동시 지원에도 정원을 초과하지 않는다.
- [ ] 모집 마감 시 큐 규칙상 불가능한 인원이면 파티를 취소할 수 있다.
- [ ] 서로 다른 인스턴스에 붙은 참가자 전원에게 제안을 동시에 전달할 수 있다.
- [ ] Discord 다이렉트 메시지 알림을 예약·회수하고 중복 발송하지 않는다.
- [ ] 만료 처리와 알림 정리를 자동으로 수행한다.

## 12. MVP에서 제외하는 기능

- PUBG와 Steam 게임 지원
- Riot Sign On을 통한 계정 소유 검증
- MMR 기반 추가 제한의 재현 — Riot API로 조회할 수 없다
- 마스터 이상 티어의 솔로·듀오 랭크 매칭
- Discord 전용방 자동 생성과 정리
- Web Push 알림
- 일치도 점수와 조건 자동 완화
- 반복 예약
- 평가·차단·신고와 내부 신뢰도
- 과거 이용 내역과 매칭 템플릿
- 운영자 관리 화면
- 자체 음성통화·영상통화
- 사용자 간 금전 거래
- 자유 게시판 중심의 커뮤니티
- 게임 계정 비밀번호 직접 수집
- 사용자를 Discord 음성방에 강제로 접속시키는 기능
